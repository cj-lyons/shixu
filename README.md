## 拾序可以做什么

### 1. 先记下来，让脑子腾出空间

临时出现的事情先放进收件箱；未来的事通过“安排以后”提前记下，到了当天进入今日安排和原清单。再按需要分到集中处理、交接与等待。区分“我来做”和“等别人做”，把负责人、完成标准和下一步记清楚。

### 2. 一次推进一件重要的事

每天选一件核心任务，用番茄钟留出专注时间。本段目标、进展记录和继续位置，帮助你在下次回来时接着做；突然想到别的事，可以先“记下打扰”。

### 3. 让休息成为工作流程的一部分

专注、短休息和长休息按自己的状态安排。另有独立的活动与喝水提醒，可关闭的空闲判断、会议暂停和跟随花色的小卡片；托盘收起后继续运行。不必把所有事情完成，才允许自己休息。

### 4. 花语、精力和音乐，放在同一个工作台

16 种花卉主题，可编辑的花笺寄语，三种精力状态与配乐选择。计时旁控制音乐，底部迷你播放器随手播放、暂停。本机曲库由你选择，安装包不附歌。

### 5. 办公室和家里，继续同一份任务

桌面端可通过坚果云 WebDAV 同步任务和已保存的专注记录，保留冲突供你处理。修改先存本机；音乐文件、运行中的计时和花笺寄语暂不参与同步。

## 第一次使用

1. **记一件事**：先存进临时收件箱，不必马上安排所有细节。
2. **选一件今日重点**：写下这一段准备推进什么，开始专注。
3. **到点休息，再继续**：记下进展与继续位置，让下一段更容易开始。

有可用托盘时，关闭窗口会收起到托盘，提醒继续运行；从托盘选择“退出拾序”才完全停止。托盘初始化失败时关闭窗口会退出。

## 数据与同步

个人任务保存在本机 SQLite 数据库。通过软件 **数据 → 备份数据** 生成一致性备份，不要直接复制运行中的 SQLite 主文件。GitHub 只管理代码，不能替代个人任务的同步或备份。

坚果云使用第三方应用密码，在软件内填写。两台桌面客户端使用相同账号和同步目录：修改后约 30 秒同步，每 10 分钟定时检查，也可立即同步；程序完全退出后不会自动同步。Linux 保存应用密码需要可用的系统密钥环。

| 参与同步 | 留在本机 |
| --- | --- |
| 任务、完成状态、交接信息、已保存的专注记录 | 正在运行的计时、音乐文件、播放状态与音量、花笺寄语 |

> 项目仍在持续迭代。曾发生本机数据库及索引异常，已进行数据恢复和重启检查，完整诱因尚未确定。请保留独立备份，不将其作为关键事务的唯一记录；模拟 WebDAV 测试也不等于两台物理电脑的真实同步验收。

## 开发与部署

使用 React、TypeScript、Electron 和 SQLite。需要 Node.js 24.12 或更新的 24.x 版本，以及 npm。Windows 为主要日常开发环境，Linux 与 macOS 已加入原生构建机验证。

<details>
<summary>从源码运行桌面开发版</summary>

```powershell
npm ci
npm run check
npm run test:platform
npm run test:sync
npm run desktop:dev
```

开发版与日常版分别使用 ShixuDevelopment 和 ShixuDesktop 数据目录，互相独立：Windows 位于 AppData/Roaming，Mac 位于 ~/Library/Application Support，Linux 位于系统配置目录（通常为 ~/.config）。

源码修改后重新运行开发启动命令会重新构建。Ctrl+R 只重新加载已构建的界面；原生菜单、提醒和后台修改需要完全退出后重开。

</details>

<details>
<summary>音乐文件与花卉配乐</summary>

仓库不包含独立歌曲文件，包括个人曲库和自创歌曲原文件；演示视频按作者授权包含自创背景音乐片段。缺少默认音频仍可构建，相关曲目无法播放。可在播放器中选择本机音乐文件夹或导入已获授权的音频。

如需使用预设花卉配乐，在 music/ 放入 樱花1.mp3、蓝色矢车菊1.mp3、蓝色矢车菊2.mp3、向日葵1.mp3 后重新构建。原始自创曲目对应 public/audio/original-music.mp3。所有音频均被 Git 排除，上传和商业发行前须另行确认授权。

</details>

<details>
<summary>运行独立网页服务</summary>

```powershell
npm ci
npm run build
# 复制 .env.example 为 .env，并设置自己的账号及长随机密码
node --env-file=.env server/index.mjs
```

默认端口 3000。桌面自动登录、原生提醒和桌面 WebDAV 连接不能直接等同于网页版能力。公网部署前需自行配置 HTTPS、备份和访问控制。

compose.yaml 是早期本机宝塔部署示例，依赖现成的 baota-trial_default 网络，不能视为通用的一键部署方案。

</details>
